A12PartiallyKnownMultiPointer

class A12PartiallyKnownMultiPointer

A12's PartiallyKnownDocumentMultiPointer — the addressing type the message channel uses.

This is not a looser pointer; it is the type A12 puts on messages. IMessage.getErrorFieldPointer(), getReferencedFieldsPointers() and getRefOmissionErrorResponsiblePointers() all return it, and ICustomCondition.check receives the error entity as one.

The observable shape is the owner's: fullName() (the /A/B/C join, so the root pointer is "/") plus repetitionIndexes(). Unlike the exact pointer this genuinely is a name-string-plus-indexes value in A12 — PartiallyKnownDocumentMultiPointerImpl stores names and repetitions and exposes exactly those two accessors.

Domain: an index is a concrete repetition >= 1, or WILDCARD meaning all repetitions, or UNKNOWN meaning no repetition carried the searched semantic index — that class's checkValidity and the interface's javadoc — or PARALLEL_ITERATION, which A12's own runtime puts on a message although both of those leave it out (KERNEL-FINDINGS kf607). The wildcard is legal at every part here, which is the sharpest difference from the exact pointer.

There is no pointer STRING for this type, and none is invented here. A12 defines no parser and no renderer for a single partially-known pointer — enumerated over the whole kernel checkout: the type is mentioned in ten files, none of which parses or emits a pointer string for it; the impl's only String producers are fullName() (names only, no indices) and a debug toString. So this type publishes the owner's value and the owner's operations, and nothing else. A previous revision shipped a format/parse/render trio for it; that was an invented serialization of an A12-owned domain object, which the dmtool result-envelope exemption does not cover.

Arity, then one deliberate strictness. Arity is enforced, as A12 enforces it: through kernel 31.1.1 PartiallyKnownDocumentMultiPointerImpl's constructor did not compare the name count against the repetition count (while toDocumentPointer() assumed it had), and this type was deliberately stricter; since kernel 31.2 that constructor refuses the mismatch itself ("fullName and repetitions have different length"). The strictness that remains is recorded because being stricter than the kernel needs its reason written down (CLAUDE.md "A client-side refusal needs a measured kernel basis"):

  • A negative other than -5 and -6 is rejected outright. The kernel expresses that rule as a bare Java assert admitting -5 alone, so it binds under -ea (most of our test JVMs) and is silently absent in production. Its own comment says the assertion exists so the javadoc can be adapted if the set ever widens, and A12's own runtime has widened it without that: on the one measured carrier, a rule reporting on a keyed group inside a group joined on another key, -6 reaches the message's references (kf607), and under -ea A12's own accessor raises on it. We admit the documented set plus that measured production value, and nothing else; whether -4 or -7 also reach a message is unmeasured (INTERPRETER-API-GAPS IAG16). A12PointerKernelDomainDiffTest measures both against the real factory.

Every other admission decision is measured against the owner factory rather than derived — in particular the fullName domain, which validates splitting and normalization only. "/Order$", "/Order Item", "/Order[2]" and the interior-empty "/Order//Items" are all legal there, and imposing the exact string parser's name grammar on this factory was an over-rejection. A12PointerKernelDomainDiffTest holds each decision to its own kernel entry point.

val semanticIndexValueForUnknownIndexGroup: Any?

semanticIndexValueForUnknownIndexGroup() — on a possibly-causing entity at the UNKNOWN row, the key its semantic index found no row for: a String for a text, enumeration or custom-typed index; for a number index a BigDecimal on the JVM or a number in JavaScript; for a date, time or date-time index a java.util.Date or a JavaScript Date at the instant the key names in the model's time zone. Null on every other pointer, including the error, referenced and fill-to-fix pointers, which A12 leaves without one. It takes part in equality, so each missed key is its own entity and 7 and 7.0 are two (KERNEL-FINDINGS KF683).
